# 个人店铺电商系统 — 基础功能设计

## 一、系统概述

### 1.1 项目背景
面向个人店主（单一卖家）的电商系统，支持商品管理、订单处理、消费者购物等核心电商流程。暂不接入支付模块。

### 1.2 角色
| 角色 | 说明 |
|------|------|
| **店主** | 唯一卖家，负责商品管理、订单处理、数据查看 |
| **消费者** | 浏览商品、下单购买 |

### 1.3 技术架构

```
┌─────────────────────────────────────────────────────┐
│                    前端 (Vue 3 + TS + Element Plus)    │
│  首页 / 商品列表 / 商品详情 / 购物车 / 订单 / 用户中心    │
│              管理后台 / 商品管理 / 订单管理 / 数据中心     │
└──────────────────────┬──────────────────────────────┘
                       │  RESTful API (JSON)
┌──────────────────────▼──────────────────────────────┐
│                  后端 (Spring Boot)                     │
│         Controller → Service → Mapper (MyBatis-Plus)    │
└──────────────────────┬──────────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────────┐
│                   数据层                              │
│  MySQL 8 (业务数据) + Redis (缓存/会话/验证码)           │
└─────────────────────────────────────────────────────┘
```

**技术栈明细：**

| 层级 | 技术 |
|------|------|
| 前端框架 | Vue 3 + TypeScript |
| 前端UI | Element Plus |
| 前端状态 | Pinia |
| 前端路由 | Vue Router 4 |
| 前端请求 | Axios + Interceptors |
| 后端框架 | Spring Boot 3.x |
| ORM | MyBatis-Plus |
| 数据库 | MySQL 8.0 |
| 缓存 | Redis 7 |
| 构建工具 | Maven (后端) / npm (前端) |
| 接口文档 | SpringDoc / OpenAPI |

## 三、后端 API 设计

### 3.1 通用规范

**请求格式：**
```json
// 通用请求头
{
  "Content-Type": "application/json",
  "Authorization": "Bearer <token>"
}
```

**响应格式：**
```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

| code | 说明 |
|------|------|
| 200 | 成功 |
| 400 | 参数错误 |
| 401 | 未登录 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 500 | 服务器错误 |

**分页参数：**
```
page: 1 (默认)
size: 10 (默认)
```

## 五、核心业务流程

### 5.1 商品上下架流程

```
店主操作 ──→ 点击"上架/下架"按钮
    │
    ▼
前端发送 PUT /api/product/{id}/status
    │
    ▼
后端校验：
  ├── 检查商品是否存在
  ├── 检查操作权限（必须是店主）
  └── 检查商品状态是否合法（如草稿不可直接上架）
    │
    ▼
更新 t_product 表 status 字段
    │
    ▼
返回更新后的状态
    │
    ▼
前端刷新列表，展示最新状态
```

### 5.2 商品定价修改流程

```
店主操作 ──→ 进入商品编辑页
    │
    ▼
修改价格字段（原价/促销价）
    │
    ▼
前端校验：
  ├── 促销价 < 原价（校验通过）
  └── 价格不能为负数或0
    │
    ▼
前端发送 PUT /api/product/{id}
    │
    ▼
后端校验：
  ├── 促销价必须小于原价
  ├── 价格必须大于0
  └── 库存必须 >= 0
    │
    ▼
更新 t_product 表
    │
    ▼
返回更新结果
```

### 5.3 商品新增流程

```
店主操作 ──→ 点击"新增商品"
    │
    ▼
填写商品信息表单：
  ├── 基本信息（名称、副标题、分类）
  ├── 商品描述（富文本编辑器）
  ├── 商品图片（支持多图上传）
  ├── 价格设置（原价、促销价）
  ├── 库存设置
  └── SKU规格设置（颜色、尺寸等多属性组合）
    │
    ▼
前端校验所有必填项
    │
    ▼
前端发送 POST /api/product
    │
    ▼
后端校验并保存：
  ├── 插入 t_product
  ├── 插入 t_sku (多条)
  └── 返回商品ID
    │
    ▼
前端提示"新增成功"，跳转商品列表
```

### 5.4 消费者下单流程

```
消费者操作 ──→ 将商品加入购物车
    │
    ▼
进入购物车 → 选择商品和规格 → 点击"去结算"
    │
    ▼
确认订单页：
  ├── 收货地址选择/新增
  ├── 商品信息确认
  ├── 优惠券选择（可选）
  ├── 价格计算（商品总价 - 优惠 = 实付）
  └── 提交订单
    │
    ▼
前端发送 POST /api/order
    │
    ▼
后端处理：
  ├── 校验商品库存
  ├── 计算金额（应用优惠券）
  ├── 生成订单号
  ├── 插入 t_order
  ├── 插入 t_order_item
  ├── 扣减库存
  └── 返回订单信息
    │
    ▼
状态变为"待付款"
    │
    ▼
提示"下单成功，请去支付"（支付模块预留）
```

### 5.5 店主发货流程

```
店主操作 ──→ 进入订单管理 → 待发货订单列表
    │
    ▼
点击"发货"按钮
    │
    ▼
填写物流公司 + 物流单号
    │
    ▼
前端发送 POST /api/order/{id}/ship
    │
    ▼
后端校验：
  ├── 订单状态必须为"待发货"
  └── 物流单号不能为空
    │
    ▼
更新订单状态为"待收货"
    │
    ▼
返回发货成功
```

## 七、权限与安全设计

### 7.1 权限控制
- **JWT 令牌**：登录后颁发 Token，后续请求携带
- **角色校验**：店主接口需校验 role=1
- **数据隔离**：消费者只能操作自己的订单/收藏/购物车

### 7.2 安全措施
- 密码 BCrypt 加密存储
- JWT Token 过期时间 24h
- 接口参数校验（JSR-303）
- SQL 注入防护（MyBatis-Plus 参数化查询）
- XSS 过滤（前端输入校验 + 后端转义）
